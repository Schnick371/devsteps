## Anlegen eines Doc Items mit MCP und CLI

Ein Doc-Item wird in zwei Schritten erstellt: zuerst die MD-Datei als Skeleton, dann das DevSteps-Item.

### Schritt 1: MD-Datei erstellen (optional)

Mit `devsteps_docs_new` wird eine neue Markdown-Datei mit Diataxis-konformem Frontmatter angelegt:

```json
{
  "tool": "devsteps_docs_new",
  "args": {
    "path": "docs/reference/overview.md",
    "diataxis_type": "reference",
    "title": "Überblick — Das DevSteps System"
  }
}
```

> **Wichtig:** `devsteps_docs_new` erstellt **nur die Datei** — kein DevSteps-Item. Schritt 2 ist immer erforderlich.

### Schritt 2: DOC-Item anlegen

```json
{
  "tool": "add",
  "args": {
    "type": "doc",
    "title": "Überblick — Das DevSteps System",
    "description": "# Überblick\n\nDevSteps ist...",
    "tags": ["h1", "reference", "overview"]
  }
}
```

> Das `description`-Feld enthält den vollständigen Markdown-Inhalt des Abschnitts.

### Schritt 3: Item mit Datei verknüpfen

`affected_paths` auf den Dateipfad setzen:

```json
{
  "tool": "update",
  "args": {
    "id": "DOC-042",
    "affected_paths": ["docs/reference/overview.md"]
  }
}
```

### Lokale CLI vs. MCP-Server

| Methode | `type: doc` unterstützt? |
|---------|--------------------------|
| Lokale CLI (`node packages/cli/dist/index.js add doc`) | ✅ |
| Lokaler MCP-Server (`devsteps-local`) | ✅ |
| Veröffentlichter npm-MCP-Server | ⚠️ BUG-085 — noch nicht unterstützt |

### Inhalt schreiben und aktualisieren

Der Inhalt wird direkt über `update` → `description` gepflegt:

```json
{
  "tool": "update",
  "args": {
    "id": "DOC-042",
    "description": "# Vollständiger Abschnitt\n\n## Unterkapitel\n\nText..."
  }
}
```

Kein separates Write-Tool nötig — `update` ist ausreichend.

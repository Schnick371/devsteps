# Work-First Authoring: Linking Doc Fragments to DevSteps Tasks

## Overview
The Work-First paradigm treats documentation as a byproduct of your development work.
Instead of writing docs after the fact, fragments are linked to the tasks that produced them —
enabling automatic classification boosting, BOM placement suggestions, and change propagation.

## How to link a fragment to its source task

Add `related_items` to your Markdown fragment's YAML frontmatter:

```yaml
---
diataxis: how-to
related_items:
  - STORY-123
  - EPIC-045
---

# How to configure the brake sensor
...
```

When you import or commit this fragment via `devsteps_docs_import` or `devsteps_docs_bom_commit`,
DevSteps automatically creates an `implements` link between the DOC item and STORY-123.

## How classification improves with Scrum context
With a linked STORY or EPIC, `heuristicClassify()` reads the Epic/Story titles as boosting signals:
- Epic titled "Hardware-Schnittstellen" → Reference score increases
- Story starting "Als Endnutzer möchte ich..." → How-to score increases
- No context: classification falls back to text-only patterns (existing behavior)

## BOM placement with context
`devsteps_suggest_bom_location` uses the Epic context as a fast-path for BOM section matching:
- Epic "Setup & Deployment" → Installation BOM section confidence: 0.87 (vs. 0.52 for tag-only)

## Author checklist
- [ ] Add `related_items` to each new fragment before committing
- [ ] Good Epic titles pay off: "Hardware-Schnittstellen API" classifies better than "Sprint 5"
- [ ] After import, verify link in `mcp_devsteps_get(doc_id)` → `.links`

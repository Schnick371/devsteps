## Die DOC BOM — Struktur und Zweck

Die **BOM** (Bill of Materials) ist das Inhaltsverzeichnis eines Gesamtdokuments. Sie ist in der Datei `.devsteps/docs-map.json` gespeichert und bildet die hierarchische Struktur aller Doc-Item-Kapitel als flache Adjacency-List ab.

### Warum eine externe Datei statt eines neuen ItemTypes?

Die Frage ob ein eigener ItemType (`docmap`, `publication`, `manifest`) sinnvoll wäre, wurde in ADR-S2-12 explizit entschieden: **NEIN**.

- **ARCH-NNN sind Manifest-Schlüssel**, keine Lifecycle-Entitäten — sie haben keinen Status, keinen Autor, keine Eisenhower-Quadrant
- Ein neuer ItemType würde `docs-map.json` und das Item-System als parallele Quellen der Wahrheit (SSOT-Konflikt) erzeugen
- Kein Industrie-Präzedenz in Task-Tracking-Systemen (Jira, Linear, GitHub Projects) für einen Dokument-Manifest-ItemType
- `enum-sync.test.ts` CI-Snapshot bricht by-design bei jedem neuen ItemType ab (8–10 Pflichtstellen in 4 Packages)

**Standards wie EPUB, IIIF, DITA nutzen First-class-Manifests nur bei Inter-System-Publishing — das trifft auf DevSteps nicht zu.**

### Struktur: Adjacency-List mit ARCH-NNN

Die BOM nutzt ein flaches Array von Knoten (`nodes[]`). Die Baumstruktur wird zur Laufzeit aus `parent_id + order` abgeleitet — kein verschachteltes JSON.

```json
{
  "version": "1",
  "nodes": [
    {
      "id": "ARCH-001",
      "doc_id": "DOC-002",
      "parent_id": null,
      "order": 10,
      "title": "DevSteps Referenz-Handbuch",
      "description": "diataxis_type: reference | language: de | Komplettes Referenz-Handbuch",
      "devsteps_items": []
    },
    {
      "id": "ARCH-002",
      "doc_id": "DOC-003",
      "parent_id": "ARCH-001",
      "order": 10,
      "title": "Überblick — Das DevSteps System",
      "devsteps_items": []
    }
  ]
}
```

### Tiefenebenen L0–L3

| Level | `parent_id` | Zweck |
|-------|-------------|-------|
| L0 | `null` | **Root-Knoten** — repräsentiert das Gesamt-Dokument |
| L1 | ARCH-NNN (L0) | H1-Abschnitt (Top-Level-Kapitel) |
| L2 | ARCH-NNN (L1) | H2-Abschnitt |
| L3 | ARCH-NNN (L2) | H3-Abschnitt |

### Verbindung zu DOC-Items

Jeder Knoten kann ein `doc_id`-Feld tragen, das auf ein `DOC-NNN` Item zeigt. Das DOC-Item enthält den eigentlichen Inhalt im `description`-Feld sowie in der zugehörigen `.devsteps/items/docs/DOC-NNN.md`-Datei.

> Das Root-ARCH-NNN (`parent_id: null`) wird per Konvention immer mit einem DOC-Item verknüpft, das Titel, Abstract und Diataxis-Typ des Gesamtdokuments enthält.

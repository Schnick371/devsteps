markdown-it plugins run synchronously but getItem() is async. Bridge: add a Map<string, ItemMetadata> (itemCache) to extension.ts populated at activate() via listItems() and kept current via a FileSystemWatcher on .devsteps/items/**/*.json. The watcher fires on create/change/delete, calling getItem() async and updating the cache. The existing devstepsWatcher only watches the .devsteps directory root (not items inside) — this is a new, scoped watcher. Cache staleness window (one FSW event cycle) is acceptable for preview rendering — no data-loss risk since preview is read-only. Phase C.

The Zod schema at packages/shared/src/schemas/analysis.ts rejects all planning/session IDs that don't match pattern ^(EPIC|STORY|TASK|REQ|FEAT|BUG|SPIKE|TEST|DOC)-\d{3,}$. This causes ALL ad-hoc planning sessions (e.g., coordination sessions, sprint planning) to silently fall back to informal tmp/ writes — creating and perpetuating the two-system problem.

Fix: Extend the regex to also accept PLAN-{session} prefix (e.g., PLAN-TMP-FORMAL, PLAN-SPRINT-001), or add a separate optional planning_session_id field.

Affected: packages/shared/src/schemas/analysis.ts (line ~94), write_analysis_report MCP handler

Note: This is the root-cause fix that unblocks convergence — must be resolved before Schema Relaxation story can proceed.

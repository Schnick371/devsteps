## Problem

Das BOM-Schema und die tatsächlichen Daten in `ideas/docs-map.json` widersprechen sich fundamental:

### Feld-Name Mismatch
- **Schema** (`.devsteps/docs-map.schema.json`): `devsteps_items` (Plural, required, Array)
- **Daten** (`ideas/docs-map.json`): `devsteps_item` (Singular, nur bei 1 von 17 Nodes)

### doc_id Pattern Mismatch  
- **Schema**: `\"pattern\": \"^DOC-[0-9]+$\"` (erwartet DOC-NNN)
- **Daten**: `\"doc_id\": \"deployment-lifecycle\"` (Slugs statt DOC-NNN)

### required vs vorhanden
- **Schema**: `\"required\": [\"id\", \"parent_id\", \"order\", \"title\", \"devsteps_items\"]`
- **Daten**: 16 von 17 Nodes haben KEIN `devsteps_items` Feld → alle invalide gegen eigenes Schema

## Ursache

Das Schema wurde nach den Daten geschrieben und hat die tatsächliche Slug-Konvention nicht berücksichtigt. Die `ideas/`-Daten stammen aus einem älteren Projekt (Remarc Deployment), das DevSteps BOM-Schema wurde für die neue DevSteps-Welt designed.

## Fix-Optionen

A) Schema an Daten anpassen (Slugs erlauben, devsteps_items optional)
B) Daten an Schema anpassen (DOC-NNN zuweisen, devsteps_items Feld hinzufügen)
C) Beides: Schema leicht lockern, Daten für DevSteps-Projekte strikt halten

## Empfehlung

Option A — Schema lockern: `doc_id` Pattern auf `^[a-z0-9-]+$|^DOC-[0-9]+$` ändern. `devsteps_items` optional machen. Dies erhält Backward-Compatibility mit bestehenden Projekten.

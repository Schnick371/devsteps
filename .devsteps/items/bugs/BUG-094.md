## Problem

`packages/shared/src/core/add.ts` nutzt `writeFileSync` in Zeile ~100 ohne vorheriges `mkdirSync(recursive: true)` für das Type-Verzeichnis. Wenn ein ItemType-Verzeichnis nicht existiert (z.B. `items/tests/` bei Projekten, die vor Einführung des `test`-Types initialisiert wurden), crasht `mcp_devsteps_add type=test` mit ENOENT.

## Reproduktion

1. Projekt wurde vor test/doc Type initialisiert (kein `items/tests/` Verzeichnis)
2. `mcp_devsteps_add type=test title=\"Test Spec\"` → ENOENT

## Erwartetes Verhalten

`addItem()` sollte `mkdirSync(itemDir, { recursive: true })` vor dem `writeFileSync` aufrufen. Das ist defensiv und kostenlos (recursive: true ist idempotent bei existierendem Verzeichnis).

## Betroffene Stelle

`packages/shared/src/core/add.ts` Zeile ~100:
```typescript
const itemDir = join(devstepsDir, typeFolder);
// FEHLT: mkdirSync(itemDir, { recursive: true });
writeFileSync(metadataPath, JSON.stringify(metadata, null, 2));
```

## Auswirkung

Jeder neue ItemType, der nach `init` eingeführt wird, funktioniert nicht bis `doctor --rebuild` oder manuelles mkdir ausgeführt wird.## Resolution

Added `mkdirSync(itemDir, { recursive: true })` before `writeFileSync` in `packages/shared/src/core/add.ts`. Ensures type directories (e.g. `items/tests/`) are created on first item add.

183 tests passing, no regressions.

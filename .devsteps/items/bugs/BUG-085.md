## Problem

Das MCP-Tool `add` im **npm-publizierten** MCP-Server akzeptiert `type: "doc"` nicht. Der Typ ist im Zod-Schema in `packages/shared/src/schemas/index.ts` vorhanden und funktioniert im lokalen CLI (`node packages/cli/dist/index.js add doc`), aber die `type`-Enum im publizierten MCP-Server-Tool ist als hardcodierte Liste definiert und wurde nicht aktualisiert.

Spürbar in VS Code Chat: Wenn `mcp_devsteps_add` mit `type: "doc"` gerufen wird, gibt es einen Schema-Validierungsfehler.

## Ursache

`packages/mcp-server/src/tools/crud.ts` (und ggf. `system.ts`) nutzen möglicherweise eine hardcodierte `type`-Liste statt dynamisch aus `ItemType.options` zu derivieren.

Laut Repository Memory: `MCP tool enums in system.ts and crud.ts now derive from Zod ItemType.options` — dies muss für die aktuelle Version des publizierten Pakets bestätigt werden.

## Akzeptanzkriterien

- [ ] `mcp_devsteps_add` mit `type: "doc"` funktioniert in der publizierten Version
- [ ] Enum-Sync-Tests (`enum-sync.test.ts`) decken diesen Fall ab
- [ ] Bei zukünftigen neuen Item-Typen: kein manuelles Update der Tool-Enums nötig

## Problem

`documented-by` and `documents` relations are intended to link `doc` items to OTHER work item types (epic, story, task, bug, spike). However, the current validation does NOT prevent `doc → doc` links via `documents` / `documented-by`.

The **only** valid doc-to-doc relationship is structural: via the BOM adjacency list (`parent_id` in `docs-map.json`). Using `documented-by` between two doc items would create a confusing double-link layer — BOM structure PLUS relation graph — with no clear semantics.

## Rule to Enforce

```
doc --[documents]--> story | task | bug | spike | epic | requirement | feature | test
                                   ✅ valid

doc --[documents]--> doc   ✅ FORBIDDEN — use BOM parent_id for doc-to-doc structure
doc --[documented-by]--> doc  ❌ FORBIDDEN

story --[documented-by]--> doc  ✅ valid (inverse of above)
```

## Required Changes

### 1. `packages/shared/src/core/validation.ts`
Add guard after existing `doc implements` guard (lines ~180, ~278):

```typescript
// Doc → doc via documents/documented-by is forbidden — use BOM structure instead
if (sourceType === ITEM_TYPE.DOC && targetType === ITEM_TYPE.DOC) {
  return {
    valid: false,
    error: 'Doc-to-doc links via documents/documented-by are not allowed',
    suggestion: 'Use docs-map.json BOM structure (parent_id) for doc-to-doc relationships',
  };
}
```

Guard must apply for BOTH `documents` AND `documented-by` directions.

### 2. MCP server — `devsteps_link` tool description

### 3. CLI — `devsteps link` error message
When the guard fires, error message should clearly state: "Doc-to-doc links are not permitted. Use `devsteps_docs_bom_commit` to establish doc-to-doc hierarchy."

### 4. `.devsteps/config.json` — `forbidden_links`
Add entry:
```json
{ "source": "doc", "target": "doc", "relation": "documents", "reason": "Use BOM structure" },
{ "source": "doc", "target": "doc", "relation": "documented-by", "reason": "Use BOM structure" }
```

## Why This Matters

The BOM adjacency list (parent_id) is the authoritative source for doc hierarchy. If `documented-by` links are allowed between doc items, two competing hierarchy representations exist — breaking the single-source-of-truth invariant.

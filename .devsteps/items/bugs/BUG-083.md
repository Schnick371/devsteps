## Bug Description

`doc` (and parentless `test`) items do not appear in the extension flat view TreeView.

## Root Cause (4-file cascade)

1. **`methodologyDetector.ts`** — no explicit `doc` or `test` case; both fall through to `return 'scrum'` default, but doc items never appear in Scrum Items because they are silently swallowed.
2. **`flatViewBuilder.ts`** — only emits `scrum` and `waterfall` methodology sections; no `'cross-cutting'` section exists.
3. **`methodologySectionNode.ts`** — type union is `'scrum' | 'waterfall'` only; must be widened to include `'cross-cutting'`.
4. **`devstepsTreeDataProvider.ts`** — `expandedSections` Set and related logic assumes only 2 section types.

## Scope
- Extension-only fix. No changes needed in shared, CLI, or MCP.
- `doc` = cross-cutting (not Scrum, not Waterfall). `test` items without a parent also fall into cross-cutting.
- `docs.json` index exists in `.devsteps/index/by-type/docs.json` (currently empty — latent bug).

## Fix Approach
1. `methodologyDetector.ts` — add `doc` to cross-cutting (return 'cross-cutting'); add fallback for parentless `test` items
2. `flatViewBuilder.ts` — add cross-cutting section (emit only when `crossCuttingItems.length > 0`)
3. `methodologySectionNode.ts` — widen type union; update label/icon for cross-cutting section
4. `devstepsTreeDataProvider.ts` — include cross-cutting in expandedSections logic

## Problem

DOC-001 bis DOC-058 haben Tags als einzelnen komma-separierten String in einem Array-Element gespeichert:

**Ist:** `\"tags\": [\"adr,decision,path-c,accepted,madr,spike-046\"]`
**Soll:** `\"tags\": [\"adr\", \"decision\", \"path-c\", \"accepted\", \"madr\", \"spike-046\"]`

DOC-059 (neuerer Import) hat das korrekte Format.

## Ursache

Vermutlich wurden die Tags beim initialen Batch-Import als komma-separierter String übergeben statt als Array-Elemente. Der `addItem()` Code nimmt Tags direkt ohne Splitting.

## Auswirkung

- Tag-Filter (`mcp_devsteps_list tags=[\"adr\"]`) findet DOC-001 NICHT, weil der Tag `\"adr,decision,...\"` heißt
- Extension TreeView Tag-Gruppierung funktioniert nicht korrekt
- 58 von 59 DOC-Items betroffen

## Fix

Batch-Update Script: Für jedes DOC-Item mit Single-Element-Tags-Array → split bei Komma → einzelne Elemente speichern.## Resolution

Batch-fixed 58 DOC items (DOC-001 through DOC-058): split comma-separated tag strings into proper arrays. DOC-059 was already correct.

Example: `[\"adr,decision,path-c\"]` → `[\"adr\", \"decision\", \"path-c\"]`
